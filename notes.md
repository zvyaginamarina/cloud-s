### Фактическое поведение:

- /serviceA/hello → App-1, /serviceB/hello → App-2, напрямую и через шлюз
- /actuator/health работает на сервисах, недоступен через шлюз
- /actuator/info включён, но пустой
- Неизвестный путь → 404, HTML Whitelabel
- Остановленный сервис → 500 от шлюза
- Валидация параметров есть в сервисе 1 (детали ещё не смотрела)
- Лог пишется в target/test-logs-ms1/requests.log, режим APPEND

### Найденные проблемы:
- Записи в requests.log пишутся без переносов строк — файл нечитаем, парсится только вхождением подстроки
- Имя лог-файла в README (user_requests.log) не совпадает с фактическим (requests.log)
- Шлюз при недоступном сервисе отдаёт 500 вместо 502/503
- Ошибки шлюза приходят HTML-страницей вместо JSON
- /actuator/info включён, но пуст — нет версии и метаданных
- README обещает мониторинг, не оговаривая, что через шлюз actuator недоступен
- Лог пишется в target, очищается при mvn clean
- Таймауты на маршрутах шлюза не заданы
- Валидация есть только в первом сервисе — асимметричное поведение одинаковых по назначению эндпоинтов
- Валидация построена на чёрном списке символов: обходится кодированием, блокирует легитимные значения
- OpenAPI-спека расходится с поведением: параметр помечен обязательным, 400 не задокументирован
